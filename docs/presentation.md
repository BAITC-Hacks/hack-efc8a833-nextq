# Qala Lab — презентация проекта

## 1. Решение городского бюджета — это выбор компромиссов

Пять районов, десять показателей, ограниченные 100 единиц. Улучшение среднего не гарантирует улучшения слабейшего района. Команда должна выбрать ровно пять уникальных мер.

## 2. Игровой цикл

Кейс → пять решений → проверка бюджета и конфликтов → расчёт → объяснение → допустимое улучшение → сравнение. Участники получают одинаковые условия одного кейса. Районные и городские меры дают разный охват.

## 3. Прозрачная модель

Лаг проекта уменьшает реализованный эффект. Три фиксированные синергии усиливают совместимые программы. Score учитывает среднее, слабейший район и штраф за каждый индекс ниже 40. Цены, ограничения и формула заданы на сервере. Контрольный пример: 95 единиц, Score 52.55768→56.54307, критических показателей 2→0.

## 4. AI с конкретной ролью

NVIDIA/OpenAI создаёт условия нового учебного кейса и объясняет переданный расчёт. Проверяемый домен считает числа. Генерация ограничена схемой, кейс подписан сервером, AI не управляет ценами и формулой. Без провайдера готовые кейсы остаются доступны.

## 5. Техническое доказательство

Чистая TypeScript-модель, Next.js transport/UI, строгий JSON, тесты контрольных значений и нарушений правил, Chromium E2E. Docker standalone и Kubernetes с probes, ограничениями ресурсов и непривилегированным процессом. README содержит воспроизводимый запуск и curl-контроль.

## 6. Применимость и следующий шаг

Подходит для учебных управленческих игр и обсуждения распределения ресурсов. Реализм основан на пространственных целях, задержке эффекта и явных конфликтах. Для реального планирования нужны подтверждённые данные, калибровка эффектов, сценарии неопределённости и экспертиза городских специалистов. Для публичного сервиса — общие квоты, авторизация и серверное хранение команд.

Во время выступления показывайте работающий основной кейс по [демо-сценарию](demo-script.md). Скриншот и AI-текст не заменяют живую проверку расчёта.
